01 / STATE

The flags hold the decision.

simulation_started permits work.
should_stop requests exit. Setting a flag is a memory update.

02 / NOTIFICATION

Broadcast wakes the waiters.

wakeup_cond is the condition variable. A broadcast tells its current waiters to check shared state again.

03 / MUTEX

They check while locked.

Each awakened thread reacquires state_mutex. Main must unlock before a waiter can complete that reacquisition.

1. Fix the mutex argument in monitor_wait()monitor.c · lines 40–41
You pass &data->monitor.has_state_mutex, a pointer to a boolean. The wait needs the actual mutex:
pthread_cond_wait(&data->monitor.wakeup_cond,
    &data->monitor.state_mutex);
has_state_mutex only records successful initialization for cleanup. It cannot lock anything. Passing it is a type error, not a way to test wait failure.

 
2. Notify waiters on every stop paththread.c · lines 28–30 / monitor.c · request_stop()
Your creation-failure path and request_stop() currently set the stop flag without broadcasting. Add the notification while holding the state mutex, before unlocking and joining. Your clock-failure path already broadcasts.
/* state_mutex is already held here */
data->monitor.should_stop = true;
pthread_cond_broadcast(
    &data->monitor.wakeup_cond);
Do not call a helper that locks state_mutex while already holding that mutex.

 
3. Join created threads after clock failurethread.c · run_simulation() / main.c · failure branch
start_simulation() broadcasts cancellation, then your run_simulation() immediately returns false. Main then cleans up. The coders may still be using those objects. Join every successfully created thread before permitting cleanup.
If a join fails, record it and attempt the other joins. Do not clear that thread’s creation flag or assume its shared data is safe to free.

#include "codexion.h"
#include <pthread.h>

static bool	create_coders(t_data *data)
{
	int		i;

	i = 0;
	while (i < data->config.number_of_coders)
	{
		if (pthread_create(
				&data->coders[i].thread,
				NULL, coder_routine,
				&data->coders[i]) != 0)
		{
			pthread_mutex_lock(&data->monitor.state_mutex);
			data->monitor.should_stop = true;
			pthread_mutex_unlock(&data->monitor.state_mutex);
			while (i-- > 0)
			{
				pthread_join(data->coders[i].thread, NULL);
				data->coders[i].thread_created = false;
			}
			return (false);
		}
		data->coders[i].thread_created = true;
		i++;
	}
	return (true);
}

static bool	start_simulation(t_data *data)
{
	int	i;

	pthread_mutex_lock(&data->monitor.state_mutex);
	data->start_time = get_time_ms();
	if (data->start_time == -1)
	{
		data->monitor.should_stop = true;
		pthread_cond_broadcast(&data->monitor.wakeup_cond);
		pthread_mutex_unlock(&data->monitor.state_mutex);
		return (false);
	}
	i = 0;
	while (i < data->config.number_of_coders)
	{
		data->coders[i].last_compile_start = data->start_time;
		i++;
	}
	data->monitor.simulation_started = true;
	pthread_cond_broadcast(&data->monitor.wakeup_cond);
	pthread_mutex_unlock(&data->monitor.state_mutex);
	return (true);
}

bool	run_simulation(t_data *data)
{
	if (!create_coders(data))
		return (false);
	if (!start_simulation(data))
		return (false);
	return (true);
}


 
What if monitor_wait() returns false?
The helper returns to the monitor routine. Then break exits only the gate loop. If the error path requested stop, the monitor’s second while (!should_stop) is skipped. The routine unlocks and returns; only then does that thread finish.
Why record wait_error separately?
should_stop answers “should we exit?” A stored error answers “did this run fail?” It is an integer result, not another start gate. After joins, the simulation must report recorded errors to main. The helper is optional organization; checking results is still needed.
A successful condition wait returns zero. A nonzero code can occur before the thread sleeps. Invalid pointers, wrong ownership, and robust mutex errors cannot all use one universal recovery handler. Confirm valid objects and mutex ownership before attempting state updates. This lesson’s interactive failures use creation and clock failures with valid synchronization objects.
