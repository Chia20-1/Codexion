Created first does not mean runs first.

pthread_create(&thread_a, ...) makes Thread A runnable. Before A actually gets CPU time, main may create Thread B—and the scheduler may let B acquire lock_a first.

What create and join guarantee

  • pthread_create(A) happens before pthread_create(B) in main.
  • It does not guarantee A executes its worker before B.
  • pthread_join(A) waits for A; it does not give A priority.
  • The first worker scheduled far enough to acquire lock_a prints first.

Why there is no deadlock

Both threads request the mutexes in the same order:

lock_a→lock_b

Only one thread can pass lock_a. The other waits before holding either lock, so a circular wait cannot form.

Best practice: release nested locks in reverse order—lock_b, then lock_a.
